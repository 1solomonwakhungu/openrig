# OpenRig 0.6.1-fork.3: every coding CLI as a first-class seat

This fork release makes the registry runtimes (Cline, OpenCode, Kilo, Gemini,
Qwen, Aider, Copilot, Cursor, Grok and Antigravity) behave much more like the
built-in Claude Code and Codex seats. You can see which CLIs are installed and
signed in, set each seat's permissions, read its usage and cost, get context
alerts, and follow it when it needs input. It also adds three runtimes (Goose,
Kiro and Oh My Pi), runtime fallback, a slower-start timeout, a way to leave a
repository's tracked guidance file alone, and three mixed-runtime templates.

Each runtime's page under [docs/reference/runtimes](../reference/runtimes/README.md)
says what was verified on a live CLI and what was derived from its source or
binary. Read it before relying on a runtime for real work.

## See your runtimes and their sign-in state

```sh
rig runtimes
rig runtimes --json
```

One row per runtime: whether it is installed and its version, whether it is
signed in, whether it can resume and fork, and which guidance file it reads,
followed by install and sign-in hints and a link to its docs page. Sign-in is
read from environment variable names and each CLI's own files; OpenRig never
signs in, never reads the keychain and never prints a key. `--probe` also runs
`cursor-agent --disable-auto-update status` for Cursor. A sign-in that lives
only in the system keychain (a `copilot login` session, Antigravity's Google
sign-in, a Goose key in the keyring) shows `unknown`, as do Claude Code, Codex,
pi and Oh My Pi, which are not checked.

`rig doctor` adds one check per installed runtime. A missing sign-in is a
`warn` with a `Fix:` pointing to that runtime's page; it never fails the doctor
run. Runtimes that are not installed get one `skipped` line. `rig setup` lists
the runtimes too, and its `--json` output gains `runtimes`
([#32](https://github.com/1solomonwakhungu/openrig/pull/32)).

## Catch a model name the CLI will reject

`rig up` preflight now warns when a seat's `model:` does not look like a model
that runtime accepts, for example a bare name where OpenCode expects
`provider/model`. It checks the form of the name, not a list of models, and it
only warns: `rig up` continues. Cline flags any `model:`, because its launch
refuses one. Built-in runtimes are not checked. See "Model names" in the
[runtimes guide](../reference/runtimes/README.md)
([#35](https://github.com/1solomonwakhungu/openrig/pull/35)).

## Per-seat permissions for every CLI runtime

```sh
rig seat set-permissions <seat> --mode floor|full_bypass --reason "<why>"
rig seat set-permissions <seat> --mode inherit
```

This now works for all ten registry runtimes, not only Claude Code and Codex.
The mode takes effect on the seat's next launch, restore or handover; `inherit`
clears it. OpenRig selects the CLI's own launch flags for the mode; it does not
verify that the CLI enforces them. For Aider, `full_bypass` still withholds
`--yes-always` while its OpenRouter onboarding could appear. Claude Code and
Codex behave as before, and pi still refuses a per-seat mode
([#29](https://github.com/1solomonwakhungu/openrig/pull/29)).

## Know when a CLI seat needs you

`rig ps`, the TUI, and the parked and queue-waiting sweeps now report
**needs-input** for every registry runtime. That covers launch gates (sign-in,
folder trust, provider pickers) and prompts during work (approvals, yes/no
confirmations, update dialogs). An answered prompt clears on the next sweep.

Every prompt and busy string was read from the CLI's source or bundle; none was
captured from a signed-in screen. Busy markers start in a trial mode, so they do
not yet hold back a wake, and the `rig ps` needs-input count and the attention
reconciler still read the older activity source
([#38](https://github.com/1solomonwakhungu/openrig/pull/38)).

## See what OpenRig answered for a seat

When OpenRig answers a dialog on a seat's behalf (today, only Copilot's folder
trust for that session), it now says so:

- `rig seat status <seat>` prints, for example,
  `OpenRig trusted /repo for this session (copilot) at <time>`, with
  `trust_answers` in `--json`.
- `rig whoami` prints a `Trust:` line (`trustAnswers` in JSON when present).
- The TUI node detail and the UI seat Overview show a Trust section.

Only the current launch is shown; a relaunch that met no dialog shows none
([#33](https://github.com/1solomonwakhungu/openrig/pull/33)).

## Usage, context and cost

`rig ps --nodes --full` adds a `COST` column after `CTX`, read from each CLI's
own session records:

| Runtime | Tokens | Cost | Context in use | Context % |
| --- | --- | --- | --- | --- |
| Cline | yes | yes | no | no |
| OpenCode, Kilo | yes | yes | yes | no |
| Gemini | yes | no | yes | no |
| Qwen | yes | no | yes | yes |
| Aider | rounded | yes | yes | no |
| Goose | yes | yes | yes | no |

Costs are the figures the CLI itself computed; a cost OpenRig could only
estimate is marked `~`. Readings are the session's running totals and are
replaced on every read, never added up. A context percentage appears only when
the CLI records its context window, which today means Qwen. Copilot, Cursor,
Grok, Antigravity, Kiro and Oh My Pi report no usage. These records are
undocumented CLI formats, pinned to the version each reader was written
against; if a format changes, the reading goes empty rather than wrong
([#31](https://github.com/1solomonwakhungu/openrig/pull/31)).

## Context alerts for CLI seats

Registry seats now feed the same context-pressure health check as Claude Code
and Codex, at the same `health.context_pressure.*` thresholds (warning 95%,
critical 99% by default). An alert needs a percentage, so today only Qwen
seats can raise one; OpenRig never guesses a window. OpenRig never compacts a
CLI seat for you. Each runtime page names the CLI's own compaction setting, or
says none is known ([#36](https://github.com/1solomonwakhungu/openrig/pull/36)).

## Transcripts from the CLI's own records

```sh
rig transcript <seat> --source auto|pane|native
```

Full-screen CLIs redraw their screen, so a pane capture can lose earlier
conversation. `auto` (the default) now prefers the CLI's own session record for
Cline, OpenCode, Kilo, Gemini, Qwen and Goose, and prints a `note:` on stderr
when it does. `native` reports why when no reader exists; `pane` keeps the
previous behavior. Native entries pass through the same redaction as pane
transcripts. Antigravity has no native reader because its store could not be
verified, and the Gemini and Qwen readers were built from source rather than
live sessions ([#42](https://github.com/1solomonwakhungu/openrig/pull/42)).

## New runtimes

- **Goose** (`runtime: goose`): fresh launch, resume and fork, with
  `GOOSE_MODE` set to `smart_approve` (floor) or `auto` (full bypass), and
  telemetry always off. It reports usage, cost and transcripts. Verified on a
  live goose 1.53.0 without credentials; no prompt was sent, so the usage
  columns follow its schema ([#34](https://github.com/1solomonwakhungu/openrig/pull/34)).
- **Kiro** (`runtime: kiro`, binary `kiro-cli`): fresh launch only; no resume,
  fork or usage. **Partly derived:** only the sign-in gate was seen live. Its
  ready screen comes from strings in the binary, so readiness is strict and
  fails toward needing attention. See "Verified versus derived" in
  [kiro.md](../reference/runtimes/kiro.md)
  ([#41](https://github.com/1solomonwakhungu/openrig/pull/41)).
- **Oh My Pi** (`runtime: omp`): runs through the Pi RPC runner with its own
  state and HOME per seat, resumes from its session file, and forks. Approval
  mode is `always-ask` (floor) or `yolo` (full bypass). `pi` is unchanged
  ([#40](https://github.com/1solomonwakhungu/openrig/pull/40)).

Antigravity, already in this fork, remains **unverified**: its TUI was never
launched, and its ready and gate screens come from strings in the binary. See
"Verified versus derived" in
[antigravity.md](../reference/runtimes/antigravity.md).

## Rig spec additions

- **`fallback_runtimes`** (member): up to three other agent runtimes to try in
  order when a fresh launch finds the declared CLI missing from `PATH` or not
  signed in. A trust gate, update prompt or crash stops the chain, and a
  restore never falls back. `rig ps` marks the seat's runtime with `*` and
  prints which runtime it is really on; `declaredRuntime` appears in JSON and in
  `rig whoami`. Falling back on rate limits is out of scope
  ([#39](https://github.com/1solomonwakhungu/openrig/pull/39)).
- **`readiness_timeout_ms`** (member): how long to wait for a slow CLI to
  become ready, from 5000 to 600000 ms, on fresh launch, restore, relaunch and
  handover. Unset keeps the current waits. The timeout message now names the
  key to raise ([#30](https://github.com/1solomonwakhungu/openrig/pull/30)).
- **`guidance.tracked_file`** (rig): what to do when the runtime's guidance file
  (for example `CLAUDE.md` or `AGENTS.md`) is tracked by git. `managed_block`
  (the default) keeps today's behavior; `skip` leaves the file untouched;
  `redirect` writes OpenRig's block to an untracked file instead, such as
  `CLAUDE.local.md` for Claude Code, and skips runtimes that have none. Cline
  guidance is now written at the git root rather than the seat directory
  ([#37](https://github.com/1solomonwakhungu/openrig/pull/37)).

See [rig-spec.md](../reference/rig-spec.md) for each key.

## Mixed-runtime templates

```sh
rig specs
rig up <template>
```

| Template | Seats | Before `rig up` |
| --- | --- | --- |
| `polyglot-dev` | OpenCode builder, Gemini reviewer | Gemini needs `GEMINI_API_KEY` or Vertex AI |
| `review-pair` | Claude Code builder, Copilot reviewer | `copilot login` or `COPILOT_GITHUB_TOKEN` |
| `budget-team` | OpenCode builder, Kilo checker | No sign-in; free models |

Read each template's README first. `budget-team` sends your code, without
sign-in, to free hosted models: do not use it on private code. The templates
leave `model:` unset ([#27](https://github.com/1solomonwakhungu/openrig/pull/27)).

## For contributors

Runtime adapters can now declare optional capability hooks (usage, sign-in,
model shape, docs, transcripts, busy and activity patterns). Hooks read local
files and environment only and are time-bounded; a slow or failing hook yields
an unknown result, never a launch failure
([#28](https://github.com/1solomonwakhungu/openrig/pull/28)). The two test
suites that drive a real, signed-in Codex now run only with
`OPENRIG_E2E_REAL_CODEX=1` ([#26](https://github.com/1solomonwakhungu/openrig/pull/26)).

## Upgrade and compatibility

Claude Code, Codex, pi and terminal seats launch, resume and report as before;
their permission and context behavior is unchanged. New database migrations
apply automatically on daemon start. Every new spec key is optional, and a spec
without them behaves as it did in 0.6.1-fork.2.

Install or upgrade with Homebrew:

```sh
brew install 1solomonwakhungu/tap/openrig
```

## Known limitations

- Antigravity and Kiro screen handling is derived from their binaries and not
  confirmed on a signed-in session.
- Needs-input and busy detection for registry CLIs comes from source and
  bundles, not observed sessions.
- Usage readers depend on undocumented, version-pinned CLI formats.
- Context alerts need a CLI that reports its window (Qwen today).
- Runtime fallback covers a missing or signed-out CLI on fresh launch only, not
  rate limits or restores.
- Permission modes choose launch flags; OpenRig does not verify a CLI enforces
  them.
